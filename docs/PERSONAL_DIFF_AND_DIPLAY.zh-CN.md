# 个人版与官方差异及 DiPlay 定向迁移

核对日期：2026-10-20。官方最新发布和主分支均为 xcertplay 1.4.2（`1298fb35e29ee30e7bd849cb0e751b52aa22a13f`）；个人分支 `personal-dev` 已包含该提交及 1.4.1 的全部历史。此次不是再次合并上游，而是在既有个人版上定向移植 DiPlay 0.2.21 的四项能力。

## 与官方 1.4.2 的区别

| 项目 | 官方基础 | 个人版 |
| --- | --- | --- |
| 安装身份 | `com.shilapi.xcertplay` | `com.whoyang233.xcertplay`，桌面名“xcertplay 个人版”，固定个人签名，可与官方共存。 |
| 版本与产物 | 官方 1.4.2，各自发布变体 | 基础版本 1.4.2 / 1402，测试包显示 1.4.2B；仅构建 automotive。 |
| 设置 | 上游设置界面与翻译 | 默认简体中文、独立紧凑密度、自适应分类和滚动、固定右上角重启/退出。 |
| 启动尺寸 | 上游显示区域及像素/物理尺寸协商 | 新握手等待前台布局稳定 500 ms；真实宽高配对、长短边物理基准，默认单区域兼容、可选多区域、恢复显示默认值。 |
| 切换应用 | 上游会按窗口变化重新协商 | 过滤后台/失焦临时尺寸；原会话内同方向收缩维持比例与触控；真实分屏/旋转按需重新协商。 |
| 音频 | 上游用途分类、音质菜单、缓冲及麦克风设置 | 增加音乐/导航用途绑定和各自 0–20 编号通道；独立导航 PCM 增益 0%–200%，不改系统音量。 |
| Wi-Fi | 上游热点、手动热点及无线连接逻辑 | 首次启动失败时有界 Wi-Fi 重置/重建；可选信道策略、默认关闭的 ADB 扫描抑制。 |
| 车辆数据 | 1.4.1/1.4.2 的 JSON 车辆属性映射和 Android Car 后端 | 已移除旧 JSON 导入/解析/资源及 Android Car 属性后端；改为默认关闭的比亚迪只读 ADB 数据，六个基本量、八个胎压/胎温诊断量。 |
| 浏览器显示 | 上游网页主屏与仪表屏服务 | 当前源码已完整移除网页、服务器、证书、远程音视频转发、配置入口和构建开关；只保留本地主屏。 |
| 麦克风修复 | 官方 1.4.2 上行修复 | 已保留；此次额外增加软件 Opus 帧失败保护。 |

包名、签名不同意味着首次从官方转到个人版需要独立配置与配对；此前个人版则可用同签名覆盖升级。车辆字段、车机实际音频路由和抗干扰效果仍以实车为准。

## 本轮四项迁移

来源：[DiPlay 0.2.21](https://github.com/shihabal3amri/DiPlay/tree/6d3b8a8ce927cb4b115b8c3881f17619433e93b1)，保留 GPL-3.0 来源说明；界面在本项目 Compose 设置中自行实现，没有引入 DiPlay 的 AGPL 界面代码。

### 隐藏比亚迪通话弹窗（实验性）

参考 [#845](https://github.com/shihabal3amri/DiPlay/pull/845) 和原有 BydCallPopupGuard / Tool / Lease。位于“设置 → 音频”，默认关闭；仅 Android 10+ 且安装 `com.byd.bluetoothcall` 的设备显示。与扫描抑制共用本应用本机 ADB 密钥，只有点击授权按钮才允许申请调试授权，后台不弹授权窗。

保存并重启 CarPlay 后，仅已连接且前台运行时暂时将 `com.byd.bluetoothcall` 的包级悬浮窗 AppOp 设为忽略；打开设置、进入后台、断开或退出时恢复原始模式。辅助进程持有恢复租约，心跳停止 10 秒后尝试恢复；恢复失败保留证据，不能宣称恢复成功。使用与 DiPlay 相同的辅助进程锁目录，避免两个应用同时修改同一包的权限。

此功能不改变蓝牙通话音频、不禁用蓝牙组件、不隐藏全屏电话应用；若固件使用其他组件或不通过悬浮窗权限显示提示，需进一步适配。没有 ADB 授权或接口被固件拒绝时，功能不可用。

### 软件 Opus 异常保护

参考 [#866](https://github.com/shihabal3amri/DiPlay/pull/866)。在现有软件编码器中捕获 Concentus 的 `AssertionError` 和运行异常，丢弃失败的 20 ms 帧并尝试重置编码状态；后续帧继续编码。格式校验保留，系统编码优先和软件回退策略不变。不是对所有录音错误或所有旧固件闪退的保证。

### 通话／短暂中断后音乐恢复

参考 [#804](https://github.com/shihabal3amri/DiPlay/pull/804) 的播放状态触发方式，按本项目音频所有权逻辑适配。在 iPhone 的 NowPlaying 从暂停/停止变为播放时，尝试重新申请音频焦点，以应对固件漏发焦点恢复通知；仅获得系统许可才标记焦点已恢复。重复元数据、正常连续播放和音频数据包不重复抢焦点。现有“音频焦点”关闭时不申请，也不修改音乐/导航 PCM 增益或通道绑定。

### 有线启动超时及恢复保护

参考 [#907](https://github.com/shihabal3amri/DiPlay/pull/907)、[#841](https://github.com/shihabal3amri/DiPlay/pull/841) 和 [#876](https://github.com/shihabal3amri/DiPlay/pull/876)。首次发出 `carplay-start-session` 后 30 秒没有活动 AirPlay 会话就报告失败，复用现有有界重试；已活动、关闭或被替换的会话取消看门狗。USB 模式切换后 10 秒没有重新枚举，重新检查当前设备配置，继续现有有限尝试。

延迟重试执行前检查是否出现新的健康会话：已恢复则取消这次重试；恢复后再次断开仍需重试。连接恢复使用事件版本和现有控制器 generation 隔离，防止旧任务拆除新连接。

按本轮要求不引入临时系统栏，也没有添加相应菜单、手势或计时器；音乐时钟、氛围灯、仪表控制等其他 DiPlay 能力不在此次迁移范围。
