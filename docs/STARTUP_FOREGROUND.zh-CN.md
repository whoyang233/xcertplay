## 车机设置

在“设置 → 启动与窗口”操作，点击右上角“重启 CarPlay”保存；前台启动选项在下一次启动入口使用。

- 希望车机开机自动显示 CarPlay：开启原有“开机自启”。本次升级不改变该开关的已有值，新安装仍默认关闭。
- “启动置前台兼容（ADB）”默认开启。系统普通启动已成功时不会调用 ADB；未显示时才使用已经授权的本机网络 ADB，向本应用发一次前台启动请求。关闭它后保留普通系统启动。
- 本机 ADB 需要车机已开启传统网络调试并允许本应用的密钥。可点击本页“授权 / 检查本机 ADB”；复用音频/连接页的同一把 ADB 密钥，无需电脑。后台启动始终使用 `mayAsk=false`，不会在开机时弹调试授权。
- “最近前台启动状态”区分请求中、已确认前台、未确认、ADB 不可达、未授权和用户离开等情况。它描述最近一次启动请求；再次手动启动会刷新记录。

## 行为边界

开机请求与桌面图标一样使用 MAIN/LAUNCHER、NEW_TASK、CLEAR_TOP 和 SINGLE_TOP；ADB 路径使用相同标记，明确指向个人包名中的 CarPlayHostActivity。已有 Activity 与后台 CarPlay 会话复用，不主动关闭控制器、重置 Wi-Fi 或重做认证。

监测覆盖开机、桌面图标与 USB 入口。页面恢复到前台后确认成功，自己的对话框不会被误判为后台；约 2 秒仍未显示才发一次兼容请求，整个窗口最长 8 秒。用户按 Home、Back 或主动进入其他应用时，停止后续尝试并取消正在等待的 ADB I/O。内部启动请求带有防重入标记，即使延迟到达也不会再开启新的重试窗口。

普通 CarPlay 协议重连、音频播放和后台更新下载不触发持续置前台，不改变此前每个进程冷启动最多一次的自动更新提示。没有新增悬浮窗权限或后台常驻服务。

Android 和车机桌面可能限制后台启动；如果普通请求被拦截，兼容路径仍依赖本机 ADB 已开启、已授权且固件允许 shell 启动本应用。车机从休眠唤醒不一定发送 BOOT_COMPLETED；这类情况还取决于车机自身的自启管理。目标设备效果需要实测，不能把启动 API 返回成功视为页面已经显示。
